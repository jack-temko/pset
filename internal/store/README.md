# store

SQLite persistence layer: connection handling, schema migrations, and the
`Book`/`Page`/`Section`/`Job`/`Embedding`/`Conversation`/`Message` models.

## Dependencies

- `modernc.org/sqlite` — pure-Go driver, no cgo (driver name `"sqlite"`)
- stdlib `database/sql`

Only `internal/engine` may import this package.

## Connection behaviour

- `Open` creates an empty database file if none exists (the parent directory
  must already exist — the engine ensures it); schema setup is a separate
  `Migrate` call.
- DSN pragmas: WAL journal, `foreign_keys=1`, `busy_timeout=5000`,
  `synchronous=NORMAL`.
- `SetMaxOpenConns(1)` serialises writes — no `SQLITE_BUSY` in a CLI context.

## Migrations

`migrations` in `migrate.go` is append-only: never edit an applied entry,
always add a new one. `Migrate` is idempotent and safe to run on every open;
each applied version is recorded in `schema_migrations`. `Version` returns 0
for an uninitialised database. `LatestVersion` is the newest entry.

## Schema

Migration 1 creates the base schema; migration 2 adds full-text search,
embeddings, and conversations; migration 3 adds conversation pinning;
migration 4 adds the per-message `segments` column and clears every
existing conversation (they were test data in the abandoned raw-text
format — cleared by decision, not migrated; there is no legacy format);
the schema was then reset to a single v2 (see `design/removals.md`), which
a v1 database is refused rather than half-understood. Entity
ids are UUIDv7 strings (TEXT) generated by `newID` — unique, and
time-ordered so `ORDER BY id` stays insertion order for the queue and
listings. Foreign keys reference those UUIDs.

- `books` — one row per imported textbook PDF.
- `books` also carries `ready`, the **cached** result of `Readiness` — an
  optimization only. Readiness is derived (`ready.go`), never a stored
  claim: the old `text_state`/`index_state`/`search_state` flags are gone,
  because every bug they caused was a flag that outlived its data.
- `pages` — `id`, `book_id` (FK → books, ON DELETE CASCADE), `page_number`
  (1-based, matching poppler), `text`, `ocr_status` and `error`;
  `UNIQUE(book_id, page_number)`. **Every page gets a row, whatever happens
  to it.** `ocr_status` is `text`, `blank` (the tools succeeded and the page
  genuinely has none — a finished page, which never blocks a book) or
  `failed` (a tool errored, so the text is missing rather than absent).
  Only `failed` blocks readiness, and only `failed` is re-attempted by a
  retry, which is why `PageNumbers` deliberately omits those rows.
- `sections` — `id`, `book_id` (FK → books, ON DELETE CASCADE), `sort_order`
  (document order, unique per book), `level` (1 = top level, nesting adds
  one), `title`, `source` (`outline` from PDF bookmarks, `inferred` from
  font sizes or text patterns), `start_page`, `end_page` (both 1-based,
  inclusive); plus `sections_book_start` on `(book_id, start_page)`.
- `tasks` — `id`, `kind` (`prepare` | `homework` — the only two kinds of
  work a student starts), `book_id` (FK → books, ON DELETE SET NULL; NULL
  until the examine phase creates the book), `homework_id`, `status`
  (`queued` | `running` | `paused` | `failed` | `done`; stopping keeps the
  work, so a stopped task rests at `paused`), `fail_kind` (`transient` |
  `environment` | `permanent`), `error`, `owner` (the runner's process
  lease), `created_at`, `started_at`, `finished_at` (NULL allowed); plus
  `tasks_status_id` on `(status, id)` — the queue read.
- `phases` — a task's plan: `id`, `task_id` (FK → tasks, ON DELETE
  CASCADE), `seq` (plan order), `key` (stable address across resumes,
  `UNIQUE(task_id, key)`), `name` (server-authored display string),
  `status` (`waiting` | `running` | `done` | `failed`), `done`, `total`
  (0 means uncounted), `note` (live display text; a phase with nothing to
  do is `done` with a note saying why), `error`, `rate` (units per second,
  persisted so "about 2 min left" survives a pause and a restart),
  `created_at`, `started_at`, `finished_at`; plus `idx_phases_task`.
  **A flat ordered list — there are no child rows**, so what the engine runs
  is exactly what a student sees.
- `book_facts` — what a book has taught pset: `id`, `book_id` (FK → books,
  ON DELETE CASCADE), `key` (`page_offset` | `conventions` | `confirmed`),
  `value`, `source` (`measured` | `learned`), `hits` (how many independent
  observations agreed), `updated_at`; `UNIQUE(book_id, key)`. Re-learning
  the same value increments `hits`; a different value replaces it and
  restarts the count, because the newer observation is the correction the
  student just made.
- `pages_fts` (v2) — fts5 index over page text: `book_id` and `page_number`
  UNINDEXED, `text` indexed. Kept consistent by triggers on `pages`
  (AFTER INSERT inserts a row; AFTER DELETE removes the matching
  `book_id` + `page_number`), so every writer path — ingest, per-page OCR
  commits, reset, book deletion — stays in sync automatically.
- `embeddings` (v2) — `id`, `book_id` (FK → books, ON DELETE CASCADE),
  `page_number`, `model` (the embedding model that produced the vector),
  `vector` (BLOB of little-endian float32 words); `UNIQUE(book_id,
  page_number)` so re-embedding replaces in place.
- `conversations` (v2) — `id`, `book_id` (FK → books, ON DELETE CASCADE),
  `title`, `created_at`, `updated_at` (bumped on every appended message —
  the thread's last activity; rename/pin leaves it alone), `pinned` (v3,
  0/1, default 0).
- `messages` (v2) — `id`, `conversation_id` (FK → conversations, ON DELETE
  CASCADE), `role` (`user` | `assistant`), `content`, `segments` (v4, JSON
  array of segment objects, NULL when the message has none), `citations`
  (JSON int array of page numbers, NULL when none), `created_at`; plus
  `messages_conversation` on `(conversation_id, id)`.
- `homeworks` (v5) — `id`, `book_id` (FK → books, ON DELETE CASCADE),
  `title`, `due_date` (NULL, `YYYY-MM-DD`), `status` (`generating` |
  `ready`), `turned_in` (0/1), `source_text` (the pasted assignment),
  `created_at`, `updated_at` (bumped by content changes, not by reads);
  plus `homeworks_book` on `(book_id, updated_at)`.
- `homework_questions` (v5) — `id`, `homework_id` (FK → homeworks, ON
  DELETE CASCADE), `position` (1-based, dense; `UNIQUE(homework_id,
  position)`), `page`, `status` (`pending` | `locating` | `writing` |
  `ready` | `failed`), `error`, `question_rect` (JSON `{x,y,w,h}`,
  normalized to the page, y from the top), `transcription` (the model's
  text transcription — LLM context, never printed), `diagrams` (JSON array
  of `{label, rect}`), `guide` (JSON walkthrough, NULL until written),
  `created_at`, `updated_at`.
- `tasks.homework_id` — NULL except on homework tasks; the runner's link
  from a queued task to the outline it generates.
- `schema_migrations` — `version` INTEGER PK, `applied_at` TEXT.

A database whose recorded version exceeds `LatestVersion` comes from an
incompatible pre-release build; `Migrate` refuses it with instructions
instead of misreading it.

`books` columns: `id` PK, `sha256` UNIQUE (content identity; the re-import
key and the library filename), `file_path` (canonical copy under
`~/.pset/library/`), `file_size`, `title`, `author`, `subject`,
`page_count`, `pdf_version`, `page_width`, `page_height`, `origin_path`,
`text_state`, `index_state`, `search_state` (v2: `none` | `full` — whether
the book's pages are embedded), `created_at`, `updated_at` (RFC3339 UTC
strings).

## Model contracts

- Every entity id is a UUIDv7 string (`newID`); inserts generate it, so
  `CreateBook` / `CreateTask` mutate their argument's `ID`. Zero timestamps
  are set too. `CreateBookWithPages` inserts book **and** pages in one
  transaction — the import commits them together, because a crash between
  the two used to leave a book that could never be prepared and never be
  recovered.
- `sha256` is unique; a duplicate insert returns an error.
- Lookups return `ErrNotFound` (check with `errors.Is`).
- `Pages(ctx, bookID)` returns pages ordered by page number;
  `PageNumbers(ctx, bookID)` is the set form — the read resume marker, and
  it omits pages whose tools errored so a retry re-attempts exactly those;
  `Page(ctx, bookID, n)` is one stored page (`ErrNotFound` when absent).
- `SavePage` is an **upsert**: re-reading a page that failed is the whole
  point of a retry, so the write must replace rather than refuse.
  `PageCounts` maps book id → stored-page count.
- `CreateSections(ctx, bookID, sections)` replaces a book's sections in one
  transaction: delete all rows, insert the slice with `SortOrder` assigned
  from the slice position (input `SortOrder` is ignored). An empty slice
  clears the book. `Sections(ctx, bookID)` returns them ordered by sort
  order — nil for a book that was never indexed.
- Tasks: `CreateTask` mutates its argument (`ID`, `CreatedAt`, status
  `queued`). `QueuedTask` returns the oldest queued task — the runner is
  serial, so that is always next. `ClaimTask(ctx, id, owner)` flips
  `queued → running` under a process lease and stamps `started_at` (false
  when it was no longer queued); `SaveTask` writes the whole row,
  **`book_id` included**, because an import learns which book it is
  preparing partway through. `ActiveTasks` returns queued + running in FIFO
  order; `AttentionTasks` (failed + paused) and `FinishedTasks(ctx, limit)`
  feed the display listing. `ReclaimOrphanedTasks(ctx, owner)` requeues only
  tasks owned by a process that is gone, so a second `pset` on the same
  database cannot yank the first one's running work.
  `PruneFinishedTasks` keeps the newest 25 and returns the ids it dropped —
  history prunes itself, so there is nothing to clear by hand.
  `UnsettledTaskCount` (queued + running) guards reset.
- Phases: `UpsertPhase` is the idempotent declare path (refreshes
  name/seq/total, preserves status/progress/rate, so a resumed run finds
  its finished work); `PhasesByTask` returns plan order; `PhaseByKey`
  resolves one; `SavePhase` persists mutable fields; `ResumePhases` returns
  the failed and the interrupted phase to `waiting` and **leaves finished
  phases alone** — a retry never re-runs work that succeeded.
- Readiness (`ready.go`): `Readiness(ctx, bookID, embedModel)` computes a
  book's whole preparation state in one round trip; `RefreshReady` caches
  the result on the row. `FailedPages` lists the pages a tool could not
  read, for the sentence the book page shows.
- Facts (`facts.go`): `BookFacts`, `BookFact` and `LearnFact` back the
  per-book memory that makes locating a homework question get better every
  time a student corrects one.
- Search: `SearchFTS(ctx, bookID, query, limit)` ranks pages through
  `pages_fts` (bm25, best page first); the query is tokenised and
  phrase-quoted, so user input never becomes fts5 syntax. `TextlessPages`
  lists the covers and art dividers whose stored text is empty — retrieval
  skips them. `Embeddings`, `SaveEmbedding` (upsert), `EmbeddingModels`,
  `ClearEmbeddings` back the search phase and vector retrieval; vectors are opaque little-endian float32 blobs here —
  similarity math lives in the engine.
- Conversations: `CreateConversation` and `AppendMessage` generate ids and
  timestamps; `Conversations(ctx, bookID)` lists threads most recently
  active first with message counts; `UpdateConversation(ctx, id, title,
  pinned)` patches only the fields it is handed (nil keeps the column) and
  does not touch `updated_at`; `Messages(ctx, conversationID)` returns the
  turns in order; `DeleteConversation` removes the thread (messages
  cascade, and deleting the book removes both).
- Message shape: a user turn carries its text in `Content`; an assistant
  turn carries its ordered `Segments` (`Content` stays empty). A `Segment`
  is one block: `prose`/`code` carry `Text`, `envelope` carries `Kind` plus
  the validated JSON `Payload` exactly as shown — storage is a JSON array
  column, opaque here; the segment vocabulary is defined by the engine's
  ask pipeline.
- Homework: `CreateHomework` mutates its argument (ID, timestamps, status
  `generating`); `Homeworks(ctx)` lists refs (book sha + title joined,
  question counts, newest activity first); `UpdateHomework(ctx, id, title,
  dueDate, turnedIn)` patches handed fields only (an empty due-date string
  clears it) and moves `updated_at`; `SetHomeworkStatus` flips
  generating/ready. Questions: `InsertQuestion` appends (or honors a
  explicit `Position`); `Questions` returns the ordered outline;
  `UpdateQuestionContent` persists everything a pipeline step produces;
  `DeleteQuestion` returns the removed row and densifies positions;
  `MoveQuestion` reorders to a clamped 1-based position — repositioning is
  two-phase (negative staging slots) so the unique constraint never trips.
  `InTx` gives callbacks a transactional store view (nested `InTx` is an
  error — use the tx-level `deleteQuestion`/`moveQuestion` inside one).
  `TaskForHomework` reports the unsettled generation task, if any.
- `Reset` empties `books` + `pages` in one transaction, returning the
  counts removed; sections, embeddings, conversations, messages and fts
  rows go with their books via cascades and triggers. The schema itself
  stays at its current version.
